# Commitment Controls

AMO derives management controls from the facts already held across Demand, Work Packages, Allocations and Actuals. The controls are reporting semantics only: they do not persist a second funding/resource/recovery RAG or duplicate the underlying business state.

## Control chain

Demand → scheduled Work Package → linked delivery Work Item → named resource allocation → Project Number → Actual recovery

The purpose is to make it obvious which delivery commitments are funded, tracked, resourced and evidenced by Actuals, and to surface exceptions without requiring managers to reconstruct the position across several pages.

## Canonical definitions

### Committed Demand

A Demand is treated as committed when its canonical state is `Planned` or `In Progress`.

`Defined` is not yet treated as a delivery commitment. `Complete` and `Cancelled` are terminal. This definition is shared by all commitment-control surfaces.

### Confirmed resource commitment

The current Allocation model does not persist a separate Proposed/Confirmed state. For this increment, a saved Allocation is treated as confirmed capacity when it references a named Person and contains at least one non-zero forecast period.

This avoids introducing another user-maintained state before there is a demonstrated need to represent tentative allocations. If tentative resource planning is introduced later, confirmation belongs on Allocation rather than Demand.

### Funded / recoverable work

The canonical `projectNumber` on Demand is the evidence that the Demand has an Oracle Project Number through which Actuals can be reconciled and recovery identified.

A committed Demand with committed resource but no Project Number is therefore reported as a funding/recovery control exception.

### Delivery Work Item required

A Work Package requires a linked delivery Work Item when it is `Ready`, `In Progress` or `Blocked`.

A `Planned` Work Package is also considered due for a Work Item once its Target Start date has arrived. A future Planned Work Package is not flagged. Complete/Cancelled Work Packages are not treated as current execution-tracking gaps.

The Work Item reference remains `azureDevOpsWorkItemId` on the Work Package. When Azure DevOps Organisation and Project configuration are available, AMO derives the clickable URL dynamically rather than persisting another URL field.

### Actuals due / missing

AMO does not infer that Actuals are due merely because the calendar month has passed. ReportingModel remains authoritative for the Actual/Forecast cut-over.

An Allocation is reported as missing Actuals only when:

- ReportingModel says the month is an imported Actuals period;
- the Allocation has non-zero forecast in that month; and
- the allocated Person has no Actual effort against the parent Demand in that month.

Future or non-imported periods therefore remain Forecast and are not false-positive missing-Actuals exceptions.

### Unexpected Actuals

Observed effort against a Demand is reported as unexpected when ReportingModel identifies Actual FTE for a Person/Demand in an imported period with no corresponding planned FTE.

### Unmet Demand

Commitment Controls consume AMO's existing unmet/unallocated Demand calculation rather than maintaining a competing formula.

## Surfaces

### Dashboard

`Delivery & Funding` provides management-level counts for committed Demand, committed work without Project Number, unmet Demand, Work Packages without required Work Items, allocations with Actuals due but missing, and Actual-to-plan recovery for the latest imported Actuals period.

The associated attention list names affected Demand, Work Packages and People. Exception controls navigate to the relevant operational surface rather than ending at a metric.

### Demand

The Demand Register includes a derived Commitment presentation covering Funding, Delivery tracking, Resource and Actuals. These values are calculated from canonical records and are not saved on Demand.

### Allocations

Demand headers show Project Number and latest imported Actual/Plan context. Work Package headers show the delivery Work Item state; where Azure DevOps configuration is resolvable, an existing Work Item reference is rendered as a clickable Azure DevOps link.

### Actuals

The Actuals administration surface includes allocation reconciliation for observed Actuals which have no corresponding planned allocation in the latest imported period.

## Storage and workspace semantics

Commitment controls persist no new reporting state. Local Workspace and Remote Workspace therefore derive identical control semantics from the same repository/domain records.

The source-of-truth boundaries remain:

- Demand: portfolio state and Project Number;
- Work Package: execution planning and delivery Work Item reference;
- Allocation: named resource plan;
- ReportingModel / Actuals: observed effort and Actual-vs-Forecast period semantics.
