# Commitment Controls

AMO derives management controls from canonical Demand, Work Package, Allocation and Actuals facts. The controls are reporting/query semantics only: they do not persist a second funding/resource/recovery RAG.

## Control chain

Demand → scheduled Work Package → linked delivery Work Item → named resource allocation → Project Number → Actual recovery

## Canonical definitions

### Committed Demand

A Demand is committed when its canonical state is `Planned` or `In Progress`. `Defined` is not yet a delivery commitment. `Complete` and `Cancelled` are terminal.

### Confirmed resource commitment

The current Allocation model has no separate Proposed/Confirmed state. A saved Allocation counts as committed capacity when it references a named Person and contains at least one non-zero forecast period.

### Funding / recovery route

The canonical `projectNumber` on Demand is evidence that the Demand has an Oracle Project Number through which Actuals can be reconciled and recovery identified. A committed, resourced Demand without one is shown as **Funding missing**.

### Delivery Work Item required

A Work Package requires a linked Work Item when it is `Ready`, `In Progress` or `Blocked`. A `Planned` Work Package is also due once Target Start has arrived. Future Planned, Complete and Cancelled Work Packages are not current execution-tracking exceptions.

The Work Item reference remains `azureDevOpsWorkItemId`; AMO derives the Azure DevOps URL from Organisation/Project configuration rather than persisting a URL.

### Actuals due / missing

ReportingModel owns Actual/Forecast cut-over. An Allocation is missing Actuals only when the period has been imported as Actuals, the Allocation has non-zero forecast in that period, and the allocated Person has no Actual effort against the parent Demand in that period.

Actuals completeness and recovery variance are separate controls. An aggregate Demand may have Actuals below plan while only one contributing allocation is actually missing Actuals. The aggregate Actual/Plan pill uses ReportingModel's material-variance threshold; missing contributor Actuals are shown as a separate red exception.

### Unexpected Actuals and Unmet Demand

Unexpected Actuals use ReportingModel's existing planned-vs-observed semantics. Unmet Demand consumes AMO's existing unmet/unallocated calculation rather than defining another formula.

## Operational query and navigation model

Dashboard summary KPIs navigate to the complete affected population, never to an arbitrary first record. Individual Attention Required entries may open a specific Demand or Work Package.

Dashboard navigation writes the same visible filter state available to users on the destination view:

- **No Project** → Demand / Active / Project = No Project Number / Control = Funding missing.
- **Unmet Demand** → Demand / Active / Control = Resource missing.
- **Work Items missing** → Demand / Active / Control = Work Item missing, preserving visibility of all affected Work Packages.
- **Actuals missing** → Allocations / Control = Actuals missing.

Demand filters are first-class query state. The default scope is **Active**, excluding Complete and Cancelled Demand. Users can switch to **All**. Project filtering explicitly supports **Has Project Number** and **No Project Number** rather than relying on text-box treatment of null values. Business Area, Initiative, Owner, Control Position and free-text search can be combined. Active filters are visible and individually removable.

Filter, arrange and search remain distinct concepts: filtering controls which records appear; Arrange By changes grouping/presentation; search narrows by text.

## Visual semantics

Red means an actionable control failure: Funding missing, Resource missing, required Work Item missing, or expected Actuals missing. Neutral labels provide context rather than implying an exception. Positive evidence is intentionally quieter than exceptions.

On Allocations, Project context, Actual/Plan recovery and Actuals completeness are shown independently. A below-plan aggregate does not become a red "missing Actuals" state merely because one contributor is absent.

## List usability

List pages use document-level vertical scrolling with sticky/floating headers. Wide tables retain native horizontal scrolling and expose a viewport-accessible synchronized horizontal scrollbar while the table extends below the viewport, so users do not have to reach the final row before panning sideways.

Allocation Demand/Resource search continues to use selection-on-commit combobox behaviour: typing narrows suggestions without re-rendering on every keystroke, preventing focus loss.

## Storage and workspace semantics

Commitment controls and filter state add no business-data persistence. Local and Remote Workspace derive the same controls from the same repository/domain records. Source-of-truth boundaries remain Demand for portfolio state/Project Number, Work Package for delivery tracking, Allocation for named resource plan, and ReportingModel/Actuals for observed effort and Actual/Forecast semantics.
